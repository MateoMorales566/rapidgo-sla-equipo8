# Release v0.3.0-orchestration

## Resumen

Semana 3 del pipeline RapidGo (variante 1: SLA de entregas): Airflow orquesta la
validación de calidad, el cálculo de KPIs y la publicación del reporte sobre la capa
`processed` que deja Spark Structured Streaming.

## Cambios principales

- **DAG `rapidgo_sla_semana3`** con 6 tareas, dependencias, `retries=2`, XCom y
  `schedule=None`.
- **Quality gate** sobre Parquet: columnas requeridas, filas presentes, sin `event_id`
  duplicados y sin filas inválidas.
- **Reporte atómico** `reports/sla_semana3_latest.json` con métricas, calidad y fuentes.
- **Fallo controlado** con la bandera `airflow/flags/forzar_fallo_calidad` y recuperación
  documentada.
- **Airflow 2.9.3 + pyarrow** en `docker-compose.semana3.yml`, con Dockerfile propio.
- **Runner local** `python -m semana3.orchestration` para ejecutar las mismas tareas sin
  Airflow.
- **Generador de fixture** `python -m semana3.sample_data` para demos y CI.
- **CI ampliado**: importación real del DAG, run exitoso, fallo controlado, recuperación y
  artefactos de reporte/logs.
- **67 pruebas pytest** y documentación ADR-003/checkpoint/evidencias.
- Se eliminaron los módulos duplicados `semana3/andres`, `semana3/julian` y
  `semana3/kevin`; la lógica quedó en `semana3/{config,quality,reporting,orchestration,
  sample_data}.py` y el DAG solo la conecta.

## Cómo verificar

```bash
python -m pytest -v
python -m compileall -q producer spark sla semana3 airflow/dags tests
python -m semana3.sample_data --input producer/sla_events_batch.json \
  --output reports/sample-datalake --overwrite
python -m semana3.orchestration --lake reports/sample-datalake \
  --reports reports/sample-reports
docker compose -f docker-compose.yml -f docker-compose.semana3.yml config --quiet
```

Airflow local:

```bash
docker compose -f docker-compose.yml -f docker-compose.semana3.yml up -d --build airflow
# http://localhost:8088  (admin / admin)
```
